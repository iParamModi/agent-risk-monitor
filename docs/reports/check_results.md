# Does the monitor learn to ask for information, and for the right information?

Meet, 11 Nov 2026. Selective setting only: the model itself decides whether to ask for a check and which one. Base Qwen3-8B (no training) next to the Phase B adapter (30 Oct and final). Numbers below are with the correct policies shown (plus 2 look-alikes), on the same records for all three models, unless stated. Test and OOD were only run and scored, never used to change anything.

## Findings

**1. Training teaches the model to ask. The base model mostly does not.**

| Correct policies shown | Base | Phase B, 30 Oct | Phase B, final |
|---|---|---|---|
| Asks when a check is needed, test (81 records) | 53.1 | 97.5 | 87.7 |
| Asks when a check is needed, OOD (71) | 33.8 | 97.2 | 91.5 |
| Quiet when no check is needed, test (39) | 84.6 | 89.7 | 92.3 |
| Quiet when no check is needed, OOD (41) | 92.7 | 82.9 | 80.5 |

Phase B learns *when* to ask, and it carries over to OOD. It is clearest on the T2 cases, where a tool result is in the conversation but cannot be trusted: base never asks on T2c (the fact changed after the result) and rarely on T2b (the result is about another resource: 31% on test, 0% on OOD); Phase B asks on 100% of both, on test and OOD. On T2a (the result is fresh, no check needed) Phase B stays quiet in 92% (test) and 91% (OOD).

**2. When it asks, Phase B mostly asks for the right fact.** Right check among the records where it asked: test 81.7, OOD 80.0 (base 67.4 and 75.0). When every needed check was made, Phase B's decision is right in 94-100% of records; when a check is missing, only 21-55%. **The weak point is asking, not using the answer.**

**3. It asks for only one check when two are needed.** The T5 records where two facts disagree need two checks (one per source), so the monitor can see the disagreement and escalate. Phase B asks in 94% of them but makes both checks in only 12% (test, 34 records); on the 26 T5 records added on 6 Nov it makes both in 2 of 26 and gets 2 of 26 right. With one check it sees one normal-looking fact and allows. This is the main reason selective is less safe than always on test. The final adapter was trained on 26 such records (was 10); it was not enough.

**4. Wrong policies lead to wrong checks.** With the retrieved policies (the full system), the right check among asked drops to 50.7 on test and 59.1 on OOD (correct policies: 81.7 and 80.0). The model checks the facts that the shown policies talk about, so a retrieval miss also becomes a checking miss.

**5. The final adapter asks a little less than the 30 Oct one.** Asks when needed: test 97.5 to 87.7, OOD 97.2 to 91.5; every needed check: test 72.8 to 64.2. It is quieter on test when no check is needed (89.7 to 92.3), and its calls have a few more errors (wrong arguments or unknown resources: 1-7% of calls, was 0-3%). Overall accuracy in the selective setting is about the same (test 79.2 to 82.5, OOD 83.9 to 78.6, val 85.0 to 82.5).

**For the report:** the fine-tuned monitor learns when to ask and what to ask for, also on OOD. It fails on cases that need more than one check, and it inherits retrieval errors. Possible next steps (not done): more two-check training records, or a prompt and target that ask for every source of a fact.
